# Rinkside architecture

Expo SDK 57 (React Native 0.86, React 19, New Architecture, Reanimated 4). Native projects are
generated by EAS / `expo prebuild` (CNG); `ios/` and `android/` are not committed.

```
App.js                     providers + navigation (one NavigationContainer)
src/
  navigation/routes.js     route names; detail screens live on the root stack
  theme/                   ThemeProvider, useAppTheme() → {dark, colors, fonts, spacing, radius, teamColor}
  data/teams.js            32 teams (incl. Utah Mammoth), colours, legacy ARI → UTA migration
  data/logos.js            bundled logos; TeamLogo falls back to the NHL CDN SVG
  api/client.js            fetch with TTL cache, in-flight dedupe, timeout + retry, disk persistence
  api/nhl.js               api-web.nhle.com + api.nhle.com/stats endpoints (season is dynamic)
  api/moneypuck.js         MoneyPuck CSVs (best-effort: 404s are normal → treat as "no data")
  hooks/useQuery.js        useQuery(fetcher, deps, {refetchInterval, keepPreviousData}), useNow()
  hooks/useLeague.js       standings + calibrated game-model ratings (memoised app-wide)
  hooks/useFavoriteTeam.js favourite team context (AsyncStorage)
  widgets/                 iOS home/lock screen widgets + game Live Activity (expo-widgets), see below
  analytics/               pure-JS models, unit-tested with `npm test`
  components/ui.js         T, Screen, Header, BackButton, Card, Section, PillTabs, Segmented, InfoTip,
                           TeamLogo, Headshot, Skeleton(List), ErrorState, EmptyState, LiveDot, Badge,
                           ProgressBar, SplitBar, CompareRow, StatTile, DataTable, FadeInView, tap()
  components/LineChart.js  SVG line chart with scrubbing, baseline, two-colour split, bands, markers
  components/icons.js      wrapped iconsax icons (always use these, never import iconsax directly)
  screens/                 one file (or folder) per screen
```

## Rules of the road

- **No hard-coded seasons.** Use `currentSeasonId()` / `moneyPuckYear()` from `src/utils/season.js`.
- **Fetch through `src/api/*` inside `useQuery`.** Never call `fetch`/`Papa.parse` from render, never
  define components inside components (it remounts them and drops state every render).
- **Keep data while refetching.** Show skeletons only on first load; pull-to-refresh calls `refresh()`.
- **Poll only what's live** (`refetchInterval` while a game is live; polling pauses off-screen and in
  the background automatically).
- **Lists:** `FlatList`/`SectionList` for anything that can exceed ~30 rows.
- **Styles:** `StyleSheet.create` at module scope for static styles; theme colours inline.
- **Every advanced stat gets an `info=` explanation** (InfoTip) in plain English.
- **MoneyPuck and Rotowire are optional data.** A missing file must never break a screen.

## Models (src/analytics)

| Model | What it does |
|---|---|
| `buildRatings` / `predictGame` | Bayesian-shrunk attack/defence ratings → exact Markov-chain simulation of regulation (power plays, pulled goalie, tied-late conservatism calibrated to the league's real OT rate) → win %, regulation/OT split, likeliest scores, totals |
| `liveWinProbability` | Same chain from the live state (score, clock, manpower) + projected final score |
| `goalWPA` | Win probability added by each goal |
| `excitementIndex` | Sum of win-probability movement, swings, winner's lowest point |
| `gameXG` / `shotXG` | Shot-quality model on NHL play-by-play (distance, angle, type, rebound, rush, manpower, empty net) |
| `deserveToWin` | Exact Poisson-binomial "replay these chances" win probability |
| `shrinkRate` / `goalieTalent` / `shootingTalent` | Empirical-Bayes (beta-binomial) true-talent estimates with 80% intervals |
| `projectCount` | Gamma-Poisson season projections with 80% intervals |
| `detectStreak` / `formLine` | Is a hot/cold run signal or noise (Poisson tail probability); EWMA form |
| `teamProfile` / `pythagorean` / `pdo` / `playoffLine` | Luck, pace, projected points, playoff-line cushion |

## Widgets and Live Activity (iOS only)

Built with `expo-widgets` (config plugin in `app.json`): layouts are JSX in `src/widgets/*Widget.js` and
`GameLiveActivity.js`, rendered by SwiftUI in a generated widget extension. Needs a **dev/EAS build**, not Expo Go
(`widgetModules()` returns null there, on Android and on web, and the app behaves as before).

| Piece | Role |
|---|---|
| `NextGameWidget` | small/medium + lock screen (circular, rectangular, inline): puck-drop countdown → live score → final |
| `TeamFormWidget` | small/medium: record, points, rank, L10, streak, 82-game point pace, goal diff |
| `GameLiveActivity` | Lock Screen banner + Dynamic Island for the favourite team's live game |
| `snapshot.js` | **pure, unit-tested**: picks the game, builds JSON props + timeline entries + Live Activity props |
| `useWidgetSync.js` | in `App.js`: fetch → snapshot → `updateTimeline` / Live Activity, every 30 s live, 5 min otherwise |
| `liveActivity.js` | start once per game at puck drop, update on change, end with the final score; Settings toggle |
| `links.js` | `rinkside://game/<id>` and `rinkside://standings` deep links (handled in `App.js`) |

Rules and limits:

- **A `'widget'` function is serialised into a separate runtime.** No hooks, no async, no imports of your own
  modules, no module-scope values: declare helpers *inside* the function and pass data through props.
  Do the thinking in `snapshot.js`, not in the widget.
- **Widgets can't fetch.** Data only moves while the app runs. Timeline entries carry their own expiry
  (countdown flips to "Puck drop" at start time; a live score downgrades to "Open app to refresh" after 20 min).
- **The Live Activity is updated by the app, not by a server.** It stays current while Rinkside is running
  (foreground, or background while team radio keeps it alive) and goes stale once iOS suspends the app. Reliable
  updates need an APNs push service plus `enablePushNotifications` in the plugin config; not built.
- Changing widget names, families or the plugin config needs a new native build (`expo prebuild`).
- Text uses SF fonts and team colours (no logos): images must be written to `widgetsDirectory` first.
